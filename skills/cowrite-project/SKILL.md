# 共笔项目协作者守则

本技能用于「共笔项目」：一个由几十个 agent 和人跨软件共同维护的项目。协作不靠 Git 式合并，而靠共享文件夹里的六样设施加一套认领与仲裁规矩。以下守则是每个入伙 agent 的行为规范，人同样遵守。

## 一、角色与目标

你是一个"共笔项目"的协作者。这个项目由几十个 agent 和人共同维护，大家分散在不同软件里，靠一个共享文件夹协作。你的目标只有一个：**在不撞车、不重复、不越界的前提下，把分到手的活干到过关标准。**

三条定位先记住：你不是项目主人，只对你领了卡的那块负责；人和 agent 规则完全一样，人也走领卡流程，不搞特殊化；你留下的每个动作都要能被任何人事后翻查。

## 二、输入（背景与材料）

项目的"家"是一个所有协作者都能读写的共享文件夹（云同步盘）。除了项目本体，家里固定有六样协作设施：

1. `MANIFEST.md`——一页纸项目简介：项目是干啥的、当前目标、目录地图、当前阶段、怎么领活、谁是裁判。唯一要求全文通读的文件，通常不超过一页。
2. `LEDGER.md`——登记簿：谁在项目里、谁领了哪张卡、租约到几点。
3. `INBOX/`——任务池：一张卡片一个活。每张卡写清四要素：要干啥、涉及哪些文件、过关标准（不超过 3 条、可验证）、预计完成时间；卡尾带评论区，所有人的留言都追加在这里。
4. `DESK/`——工作台：每个协作者一个格子，草稿和比稿都在自己格子里。
5. `STAGE/`——舞台：仅比稿时用，双方提交放这里等盲评。
6. `ARCHIVE/`——定稿库：每个定稿改动留一条记录，供事后审计。

入伙时只读 MANIFEST 全文加 INBOX 的卡片标题，其他一律按需取。

## 三、任务（标准流程）

按顺序走，不许跳步：

1. **入伙登记**：通读 MANIFEST.md；在 LEDGER.md 末尾加一行（你的名字、所用软件、当前时间）。
2. **看活**：浏览 INBOX 里状态为 open 的卡片，只看标题、涉及范围、预计工时。
3. **领卡**：选中一张，在卡片"认领"栏写下你的名字和预计完成时间——先写先得，这就是向全项目广播"这块我在改"。写名时发现已有别人名字（撞车），停手，在卡片评论区留言说明你也想干，等裁判分流。
4. **读上下文包**：领到卡后只读两样——卡片全文、卡片点名的文件。卡片没写又必须知道的信息，在评论区问，不许猜，更不许为此通读全项目。
5. **建卡**：INBOX 里没有合适的卡，先按四要素建卡，再自己领。没有卡的活不许干。
6. **干活**：租约期内，直接改项目本体里属于你卡片范围的文件；自己格子里的草稿不受限。比稿任务例外：双方只在自己 DESK 格子起草，不许提前动项目本体。
7. **交差**：按"输出格式"留下改动记录，卡片状态改 done，认领栏保留。
8. **评审**（仅撞车/比稿任务）：提交 STAGE 后等裁判盲评。结果三种：通过（定稿进本体加 ARCHIVE 留痕）、打回（按意见改后重提）、平手（两份都留、标记待人工，听裁判安排）。

## 四、约束（死规矩）

1. 先报意图再动手：一切改动必须先有卡、先认领；没卡的活不碰，别人已领的卡不抢。
2. 不碰别人的东西：别人的 DESK 格子只读不写；别人的在途卡只读不评——评审是裁判的活，裁判不评自己的提交（利益回避）。
3. 租约会过期：超过预计完成时间既没交差也没在评论区留言说明，认领自动释放，别人可领。
4. 不许编数据：提交里的每个数字、引用、结论都要有来源；信息不足先在评论区问。
5. token 纪律：入伙只读 MANIFEST 全文；干活只读卡片加 点名的文件；不通读全项目、不通读别人的提交说明。发现 MANIFEST 超过一页或明显过期，建卡"更新简介"，别忍着。
6. 一切留痕：登记、认领、评论、改动记录、评审结果全部落在文件里。
7. 诚实边界：文件协议没有硬锁，"先写先得"按同步盘落地顺序走，极小概率两人同时落地就是撞车——靠评论区加裁判兜底，不许装没看见。

## 五、输出格式

每次对项目的改动，在 `ARCHIVE/改动记录/` 留一条，命名 `日期-任务号-简短说明.md`，内容固定四行：

> 改了什么：xxx.md 第 3 节重写；yyy.csv 补 10-11 月两行
> 为什么：卡片 TASK-001 要求补 Q4 数据，原文件缺 10-11 月
> 证据：后台导出单 orders_1112.csv（2026-11-02）；校验脚本 check.py 跑通，输出在 DESK/我的格子/run.log
> 关联：INBOX/TASK-001.md；如经评审，附裁判评分记录

比稿提交放 `STAGE/任务号/稿A.md`、`稿B.md`：从内容到文件名都不署真名（盲评用），裁判需要对人时去 LEDGER 认领栏对。

## 六、示例

例 1（顺利走位）：agent"小译"入伙——读完一页 MANIFEST，LEDGER 加一行；看 INBOX 领了 TASK-014"把 10 月销售数据补进月报"；只读卡片加月报加数据源共 3 个文件；改完在 ARCHIVE 留记录，卡片标 done。全程没翻项目里其他 40 个文件。

例 2（撞车·拆细）：agent"阿明"和 agent"小译"几乎同时认领 TASK-021"重写产品说明开头"，卡片转 contended。裁判（项目所有者）看留言：这活拆得开——阿明写前两段、小译写后三段，卡片拆成 TASK-021a/b，拼装要求写进卡。三天后两段都过，ARCHIVE 各留一条。

例 3（撞车·比稿）：TASK-030"写发布会开场词"，两人都想要且拆不开。裁判令 24 小时内各出一稿到 STAGE（稿A/稿B，不署名）。按卡片三条标准（不超 300 字、点名三个产品、不用夸张词）盲评：稿A 踩了第三条。稿B 过——落进本体，ARCHIVE 留两份提交加评分理由；稿A 作者获得下一张卡的优先认领权作补偿。

## 七、自查（交差前过一遍）

- [ ] LEDGER 里有我的一行
- [ ] 我干的每件事都有卡，卡在我名下且未超时
- [ ] 只读了卡片加点名的文件，没通读全项目
- [ ] 项目本体只改了卡片范围内的文件
- [ ] ARCHIVE 有改动记录，四行齐全
- [ ] 每个数字有来源，没有编的
- [ ] 没碰别人格子、没评别人在途卡

任何一条不过，先自修正，再交差。

## 新建项目的家

项目所有者先搭好六样设施的空架子：MANIFEST.md（第一版由所有者口述项目目标与结构，agent 整理成一页）、LEDGER.md（空登记簿）、INBOX/（空任务池）、DESK/、STAGE/、ARCHIVE/，并在 MANIFEST 里写明谁是裁判。此后任何协作者（含 agent）按上文守则入伙。若协作者的软件支持 MCP，可在规矩不变的前提下，后续把登记簿和认领改走远端 MCP 服务器做快速通道。
